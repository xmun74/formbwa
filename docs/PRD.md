# PRD — 폼봐 (formbwa) · AI 맨몸운동 코치

> 기획명세서. 무엇을, 왜, 누구에게 만드는지 정의한다.
>
> 관련 문서: 구현 방법은 [TRD-FE.md](./TRD-FE.md)·[TRD-BE.md](./TRD-BE.md), 작업 분해·진행 상황은 [TASKS.md](./TASKS.md) 참조. 이 문서의 기능 ID(F1-1 등)는 각 문서에서 그대로 인용된다.

## 1. 제품 개요

캐릭터 코치의 **시범 영상을 보며 따라 하고**, 웹캠이 내 자세를 실시간 인식해 바로 그 순간 짧은 음성으로 교정·격려해주는 서비스. **유튜브 홈트를 따라 하듯 시범을 보되, 그 영상이 나를 마주 보고 자세를 잡아준다.**

- 비전: "움직임을 보고 코칭하는 엔진"을 만들어 맨몸운동 → 요가/필라테스 → (제휴 후) 춤으로 확장
- 한 줄 경험 목표: **"옆에서 누가 진짜 봐주는 느낌인데?"**
- 초기 시장/언어: **한국어 단일** (캐릭터 콘셉·멘트·UI 모두 한국어 전용. 글로벌은 국내 검증 후)
- 주 사용 환경 (1단계): **데스크톱/노트북 브라우저 우선.** 모바일 브라우저는 동작하되 최적화 후순위 (3단계에서 격상)

## 2. 문제 정의

- 개인 PT는 회당 5~10만원으로 비싸고, 시간·장소 제약이 크다
- **유튜브·홈트 영상을 따라 하는 게 가장 흔한 홈트 방식**이지만, 영상은 나를 볼 수 없어 내 자세가 맞는지 알 수 없다 — 따라 하기는 되는데 결국 혼자 하는 것과 같아, 부상 위험이 있고 금방 포기한다
- 기존 피트니스 앱도 운동 "전후"(계획 추천, 기록)에 집중하고, 운동 "순간"에는 일방적 영상뿐이다 — 되받아 봐주는 눈이 없다

## 3. 타깃 사용자

| 우선순위   | 대상                               | 니즈                            |
| ---------- | ---------------------------------- | ------------------------------- |
| 1차        | 홈트 입문자 (20~30대, 헬스장 부담) | 자세 불안 해소, 재미, 습관 형성 |
| 2차        | 헬스장 초보                        | 기본 동작(스쿼트 등) 자세 학습  |
| 3차 (확장) | 요가/필라테스 홈수련자             | 정적 자세 정확도 확인           |

## 4. 핵심 사용자 시나리오 (1단계)

1. 링크 접속 → **`/` 인트로** (히어로 + 제품 설명 + "시작하기"). 첫 화면은 입력 폼 없이 무엇인지만 깔끔하게 보여줌
2. "시작하기" → **`/exercises` 운동 목록**: 부위별(웜업·상체·하체·전신) 종목 조회 → 하나 선택 → 코치 선택으로
   - **운동 먼저, 코치 나중** — "뭘 할지" 정하고 "누가 봐줄지" 정하는 순서
   - **1단계는 스쿼트(하체) 1개만 실제 동작**, 나머지 부위·종목은 **"준비 중"으로 UI만 노출**(§11 스쿼트 1개). 목록·부위 구조를 미리 세워 3단계 종목 추가(F3-3) 때 화면을 다시 안 짜도 되게 — 확장을 화면이 미리 알고 있음
3. 종목 선택 → **`/start` 설정** (한 화면): **닉네임 입력** + 카메라 처리 방식 고지(§10) + 준비물·셋업 안내(웹캠, 2m, 측면 45°) + 캐릭터 코치 선택(2종) + "운동 시작"
   - **라우트 분리** (`/` → `/exercises` → `/start` → `/prepare` → `/workout` → `/summary`) — 시스템 뒤로가기가 자연스럽게 동작한다. **새로고침해도 단계가 유지되는 건 닉네임·종목·코치 선택값을 localStorage에 영속하기 때문**(인메모리 상태는 새로고침에 사라짐). 프리로드한 MediaPipe 모델은 인메모리라 라우트 전환엔 유지되고 새로고침 시엔 재프리로드된다 (TRD-FE §3.2·§9.1)
   - **설정을 별도 라우트로 두는 것이지 여러 화면으로 잘게 쪼개지 않는다** — `/start` 한 화면에 닉네임·코치가 함께 있어 자유롭게 수정. 앞 단계를 지난 시점엔 이미 마음을 먹었으므로 `/start`의 입력은 이탈 요인이 아니다
   - **닉네임은 선택 — 강제하지 않는다.** 비워도 [운동 시작] 가능(빈 값이면 "회원님"으로 호명). 필드 1개·개인정보 아님·동기 명확("뭐라고 부를까요?")이라 이탈 요인이 아니지만, 필수로 막으면 마찰이 된다. 자동 포커스 금지, 플레이스홀더로 예시 제시. localStorage 저장으로 재방문 시 이름 유지
   - `/` 인트로·`/exercises`에 머무는 동안 모델·WASM을 백그라운드로 받는다 — 읽고 고르는 시간이 곧 프리로드 시간 (TRD-FE §9.1)
   - 이 제품은 물리적 셋업이 특이하다(노트북에서 2m 물러나 측면 45°). 링크만 받은 사람은 예상하지 못하므로 카메라를 켜기 전에 알려야 한다
4. "운동 시작" → 카메라 권한 요청 → **`/prepare`**: 몸 전체 배치 안내(측면 45°) → 기립 캘리브레이션(약 3초). 이 준비 단계는 한 라우트 안에서 배치 → 캘리브레이션을 **내부 2상태로** 전환
   - **운동·준비·요약을 라우트로 분리한다** — 밝은 준비 화면(`/prepare`)·몰입 다크 운동 화면(`/workout`)·밝은 결과 화면(`/summary`)은 성격이 달라 별도 라우트로 둔다. 뒤로가기·새로고침이 자연스럽고(선택값은 localStorage 영속으로 유지), 운동 중 이탈은 화면 내 [✕ 그만두기]로 처리
5. 캘리브레이션 완료 → **`/workout`** 운동 화면: **왼쪽에 내 카메라(관절 오버레이, 작게) + 오른쪽에 코치 시범 영상(크게)** → 시범을 따라 스쿼트 → 실시간 카운트 + 짧은 음성 피드백
   - "무릎 조금 더 굽혀요" / "허리 세워요" / "좋아요, 방금 자세 괜찮았어요" / "하나만 더!"
   - **화면 위계는 입문자 중심**: 배우는 게 1순위라 시범이 주연(크게), 내 모습은 조연(작게). 종목이 늘수록(F3-3, 요가·필라테스) 매번 새 동작을 배우므로 "배우기"가 항상 주(主)
   - 다만 **내 모습이 작아도 피드백은 강하게** — "봐주는 눈"은 화면 크기가 아니라 반응 강도에서 온다 (판정 시 음성 + 자막 + 해당 관절 하이라이트)
   - **닉네임 호명**으로 "봐주는 느낌" 강화 — "민수님, 무릎 굽혀요". 교정·칭찬 음성은 사전 mp3(이름 없음)라 이름은 **자막에** 항상 노출. 음성 호명은 세트 경계(시작/끝) 등 **비-실시간 시점에만** 런타임 TTS로 (근거는 TRD-FE §1·§6.1)
   - 시범 영상은 기준 템포로 반복 재생. **초 단위 동기화 없음** — FSM이 내 스쿼트 1회를 스스로 잡아 규칙으로 판정하므로, 선생님과 템포가 달라도 정확하다 (시범은 배우기 위한 참고, 판정은 내 몸을 독립적으로 봄)
6. 세트 종료 → **`/summary`** 요약 화면: 완료 횟수, 자세 정확도, 세트 진행, 운동 시간, 가장 많이 지적된 포인트 1~2개, 캐릭터 톤의 총평 한 단락
7. (2단계~) 로그인 시 기록 저장, 누적 대시보드 확인

## 6. 캐릭터 정의 (초기 2종, 한국어 전용)

| 캐릭터         | 톤                  | 예시 멘트                     |
| -------------- | ------------------- | ----------------------------- |
| 열정 PT쌤      | 하이텐션, 응원 위주 | "좋아요!! 딱 하나만 더!!"     |
| 부산 사투리 쌤 | 구수한 잔소리       | "무릎 그래 펴면 안 된다카이~" |

3단계 추가 후보: 츤데레 코치, 군대 조교. 사투리 캐릭터는 TTS 사투리 표현 품질 검증(1단계 초기)을 통과해야 확정.

멘트 원칙: 한 번에 한 가지만 지적, 3초 이내 길이, 같은 지적 연속 반복 금지, 칭찬:지적 비율 최소 1:2 유지.

캐릭터는 음성뿐 아니라 **시범 영상의 시연자**로도 등장한다 (F1-8) — 따라 하기 정확도를 위해 **사람과 같은 관절 비율의 인체 + 캐릭터 얼굴**. 제작은 TTS와 같은 오프라인 방식(1개월 구독 → 일괄 렌더 → 해지), 상세는 TRD-FE §6.2.

## 7. 비범위 (하지 않는 것)

- 영상 저장·서버 전송 (리플레이 기능 포함) — 개인정보 리스크 등급이 달라짐
- 얼굴 인식·신원 확인 — 생체인식정보(민감정보) 해당 소지 차단
- 재활·의료 목적 코칭 — 의료기기 규제 영역
- K-pop 안무 콘텐츠 — 제휴 전까지 금지
- 웨어러블 연동, 식단 관리
- (참고) 코치 시범 영상은 앱에 포함된 **사전 제작 에셋** — 사용자 영상과 무관하며 위 "영상 저장·전송 금지" 원칙에 영향 없음

## 8. 성공 지표

| 단계    | 핵심 지표                              | 목표                |
| ------- | -------------------------------------- | ------------------- |
| 1단계   | 세트 완료율 (시작 대비 종료)           | 60%+                |
| 1단계   | 체험 후 정성 반응 ("봐주는 느낌" 언급) | 인터뷰 10명 중 6명+ |
| 2~3단계 | D7 리텐션                              | 20%+                |
| 3단계   | 주 2회 이상 운동 사용자 비율           | 30%+                |
| 4단계   | 무료→유료 전환율                       | 3~5%                |

정확도가 아니라 **재방문**이 최우선 지표. 1단계에서 "다음 날 또 오는가"가 검증 대상이다.

## 9. 수익화

- 모델: Freemium 구독 — **경계는 "운동은 무료, 데이터는 유료"로 확정**
  - 무료: 전체 운동 + 전체 캐릭터 + 세트 직후 요약 (핵심 경험은 막지 않아 리텐션·바이럴 우선)
  - 유료: AI 캐릭터 리포트, 누적 대시보드, 추이 차트, 스트릭 (데이터가 쌓인 사용자일수록 전환 동기 강화)
- 가격: 미정. 월 1만원대 가설(경쟁가 검증됨)만 두고 4단계 직전 설문/테스트로 확정
- 가격 앵커: PT 회당 5~10만원 vs 월 구독 커피 2~3잔 값
- 유입 전략: 쇼츠(캐릭터 코칭 장면) → 링크 → 설치 없이 즉시 체험 → 계정 생성
- B2C 부진 시 피벗 여지: 기업 복지/보험사 웰니스 B2B2C
